1. PROJECT SUMMARY
AI-assisted data analysis application with a FastAPI backend and an Expo /
React Native frontend. Users upload CSV, XLSX, or SQL dump files, inspect
tables and previews, search imported data, and ask natural-language questions.
Question answering uses Gemini to generate SQLite queries and explain bounded
query results. The frontend targets Expo Web and Android.

2. ARCHITECTURE AND RESPONSIBILITIES
- Frontend owns file picking, dataset/session UI state, previews, search UI,
  chat state, and HTTP calls.
- API routes validate requests and delegate to services.
- Ingestion parses supported files and creates a per-session SQLite database.
- Query service handles bounded read-only SQL execution and dataset search.
- SQLite safety validates statements and applies read-only connection controls.
- AI service calls Gemini to generate SQL and explain executed results; it
  does not open or execute the database itself.
- Lifecycle service creates UUID sessions, resolves database paths, checks
  session age, removes raw uploads, and cleans expired databases.
- GEMINI_API_KEY is a backend-only secret. EXPO_PUBLIC_API_URL configures the
  frontend API endpoint.

3. BACKEND
Entry point and routing:
- backend/main.py builds the FastAPI app, configures CORS and typed error
  handlers, runs startup and recurring database cleanup, and mounts routes.
- backend/app/api/routes.py exposes GET /health and POST /upload, /ask, /search.
- Upload supports .csv, .xlsx, and .sql, streams to a temporary file, enforces
  the configured upload limit, ingests it, removes the raw upload, and removes
  any partial database if ingestion fails.
- Ask validates the UUID session, inspects schema, requests SQL from Gemini,
  refreshes session activity, runs SQL through the read-only query path, and
  asks Gemini for an explanation.
- Search works without Gemini and optionally accepts a column or table.column.

Configuration and errors:
- backend/app/core/config.py reads ENVIRONMENT, GEMINI_API_KEY, TEMP_DIR,
  MAX_UPLOAD_MB, SESSION_TTL_SECONDS, and CORS_ORIGINS.
- Defaults: /tmp for temporary files, 20 MiB uploads, 30-minute session TTL,
  and localhost:8081 / 127.0.0.1:8081 CORS origins.
- MAX_UPLOAD_MB is clamped between 15 and 20 MiB.
- backend/app/core/errors.py defines domain error types and stable JSON error
  payloads; unexpected exceptions are logged and returned as generic 500s.
- backend/app/core/sqlite_safety.py accepts one SELECT or WITH statement,
  blocks dangerous SQL keywords and multiple statements, opens SQLite in
  read-only mode, enables query_only, and installs an authorizer.

Services:
- backend/app/services/ingestion.py reads CSV with pandas, XLSX with
  openpyxl/pandas, and bounded SQLite-compatible SQL dumps. It drops fully
  empty rows/columns, sanitizes identifiers, rejects unusable data, limits
  tables to 250 columns and 250,000 rows, and returns schema, row counts, and
  up to 10 preview rows per table. CSV/XLSX integer and floating-point
  columns retain SQLite INTEGER/REAL types. SQL dumps are limited to 2,000
  statements and a limited set of table/index/insert/transaction statements.
- backend/app/services/query.py limits SQL results to 1,000 rows and search
  results to 500. Search is case-insensitive, parameterized, supports an
  optional column selector, and ranks exact, prefix, contains, then
  all-terms matches. Search and ask refresh session activity when work starts.
- backend/app/services/ai.py uses google-genai with model gemini-2.0-flash.
  The Gemini client is cached per process. SQL generation uses a JSON response
  schema and schema-grounded prompts. Explanations use the executed SQL,
  columns, and at most 200 returned rows.
- backend/app/services/lifecycle.py creates UUID session identifiers, stores
  databases below TEMP_DIR, checks TTL, deletes raw uploads, and removes
  expired *.db files.

Tests and backend deployment files:
- backend/tests/test_ingestion.py covers CSV, XLSX, SQL dump imports, invalid
  data, oversized data frames, raw-upload cleanup, and numeric SQLite types.
- backend/tests/test_routes.py covers health, uploads and validation, upload
  size limits, expired sessions, malformed/markdown Gemini SQL responses,
  and Gemini client caching.
- backend/tests/test_sql_safety.py covers allowed SELECT/WITH statements and
  unsafe SQL rejection.
- backend/requirements.txt lists FastAPI, Uvicorn, pandas, openpyxl,
  google-genai, and python-multipart.
- backend/runtime.txt specifies Python 3.11.10.
- backend/Procfile runs Uvicorn using the platform PORT environment variable.

4. FRONTEND
- frontend/app/_layout.tsx configures Expo Router Stack, dark status-bar
  content, and a transparent blurred header.
- frontend/app/index.tsx owns session, table, chat, and search state; composes
  upload, data preview, and chat; uses API search with a local preview-only
  fallback when the request fails. Its web scroll content has additional
  top padding below the transparent header.
- frontend/src/components/UploadPicker.tsx uses expo-document-picker,
  accepts CSV/XLSX/SQL, checks a 20 MiB client-side size limit, uploads the
  selected file, and reports status/errors.
- frontend/src/components/DataPreview.tsx displays table schemas, row counts,
  preview/search results, and NULL values; includes search/clear controls and
  web glass-scrollbar styling.
- frontend/src/components/ChatPanel.tsx submits natural-language questions,
  displays messages, SQL, result tables, loading, empty, and error states.
- frontend/src/components/GeneratingIndicator.tsx provides a native-driven
  animated loading indicator.
- frontend/src/components/AnimatedBackground.tsx renders 38 low-contrast
  particles. Web uses a canvas/requestAnimationFrame; non-web uses animated
  values and a requestAnimationFrame loop, with 2D collisions and edge
  bouncing.
- frontend/src/api/client.ts reads EXPO_PUBLIC_API_URL, uploads multipart
  files (Blob/File on Web and URI metadata on native), calls /ask and /search,
  and normalizes API/network errors.
- frontend/src/types/data.ts contains request, response, table, preview-row,
  and chat-message contracts.
- frontend/src/theme/tokens.ts centralizes colors, radii, spacing, shadows,
  dot motion opacity, acrylic surfaces, and Mica backdrop styles.

5. FRONTEND CONFIGURATION
- frontend/package.json scripts: start, web, build:web, android, typecheck.
- Frontend stack: Expo SDK 52, Expo Router 4, React Native 0.76, React Native
  Web, and TypeScript 5.7.
- frontend/app.json configures Expo Router, static Metro web output, app
  metadata, and the Android package identifier.
- frontend/eas.json defines an internal Android APK preview and Android
  app-bundle production profile.
- frontend/vercel.json builds with npm run build:web, serves dist, and rewrites
  routes to index.html.
- frontend/tsconfig.json enables strict checking and noUncheckedIndexedAccess.

6. LOCAL COMMANDS
Backend (from repository root):
  cd backend
  .\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
  .\.venv\Scripts\python.exe -m pytest -q

Frontend:
  cd frontend
  npm.cmd run web -- --port 8081
  npm.cmd run typecheck
  npm.cmd run build:web

Set EXPO_PUBLIC_API_URL to the reachable backend base URL, for example
http://127.0.0.1:8000 for local web development. Set GEMINI_API_KEY only in
the backend environment; do not put secrets in frontend variables or source.
The root .gitignore excludes .env files, virtual environments, Python caches,
SQLite files, node_modules, .expo, and dist.
